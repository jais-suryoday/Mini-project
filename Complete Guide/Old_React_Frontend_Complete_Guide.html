1. Project Overview

Project Title: AI Library Seat Occupancy Tracker

In Simple Terms: This project uses a camera (webcam) and Artificial Intelligence to automatically detect how many seats in a library (or any room) are occupied and how many are vacant — in real-time. It shows a live dashboard on a web browser where anyone can see which seats are free without physically going to the library.

How it works (the "elevator pitch"):

A camera watches the library. An AI model (YOLOv8) runs on each video frame to detect people and their body outlines. The system checks which people are sitting inside pre-defined "seat zones" and marks those seats as occupied. This information is instantly pushed to a web dashboard over WebSocket, where users see a live video feed with colored seat overlays, an occupancy ring chart, and per-seat status chips — all updating in real-time.

2. Problem Statement

In college and public libraries:

  • Students waste time walking to the library only to find no seats available.
  • Library staff cannot easily track seat utilization for planning.
  • Manual seat counting is inefficient, inaccurate, and not real-time.

Solution: An automated, AI-powered, real-time seat occupancy monitoring system that requires only a standard webcam and a computer.

3. Objectives

#Objective
1Detect people in a camera feed using computer vision (YOLOv8).
2Map detected people to pre-defined seat zones to determine occupancy.
3Stream live video with occupancy overlays to a web dashboard.
4Provide real-time occupancy data via WebSocket for instant updates.
5Allow administrators to visually calibrate seat zones via a drag-and-draw interface.
6Minimize false positives through head-keypoint verification, temporal smoothing, and contour merging.

The backend lives in main.py:

  • CONFIDENCE_THRESHOLD: 0.45.

  • NMS_IOU_THRESHOLD: 0.4.
  • HEAD_KP_CONFIDENCE: 0.3; MIN_HEAD_KPS: 2.
  • OVERLAP_THRESHOLD: 0.15; OCCUPANCY_HOLD_SECONDS: 2.0.

7.2 Data Models

SeatZoneIn: normalized rectangle coordinates (x1, y1, x2, y2).

SeatZoneState: runtime state tracking occupied.

7.3 Endpoints

  • GET /health: Health status.
  • GET /seats, POST /seats, DELETE /seats/{id}: REST CRUD operations for seat zones.
  • GET /video_feed: MJPEG stream.
  • GET /occupancy: Snapshot of current occupancy.
  • WS /ws: WebSocket real-time push.

9. Key Algorithms & Techniques

  1. Head-Keypoint Verification: Requires at least 2 visible head keypoints (0-4) with confidence > 0.3 to discard inanimate objects.
  2. Torso Bounding Box: Bounded exclusively by head and shoulder keypoints (0-6) with 15% padding, excluding limbs.
  3. Best-Match Greedy Assignment: Each person is mapped exclusively to at most one seat with the highest overlap ratio.
  4. Temporal Smoothing: Holds an occupied status for 2.0 seconds after detection loss to prevent UI flickering.
  5. Union-Find Contour Merging: Merges fragmented segmentation contours into a single convex hull.

10. Viva Q&A Highlights (React Version)

  • Q: Why use React + Vite?

A: React provides reactive state-driven rendering and component modularity. Vite provides lightning-fast Hot Module Replacement (HMR).

  • Q: How does the calibrator work?

A: An HTML Canvas overlays the live video. Mouse events (mousedown, mousemove, mouseup) capture normalized coordinates that are saved to seats.json via POST /seats.

  • Q: Why do we need a dev proxy in Vite?

A: Vite runs on port 5173 while FastAPI runs on 8000. The proxy routes /ws and /video_feed requests to port 8000 seamlessly, avoiding cross-origin issues during development.
